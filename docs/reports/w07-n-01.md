## 1. Đã làm

| Mục | Ở đâu | Ghi chú |
| --- | --- | --- |
| Ma trận fail mode, 4 sự cố × 2 mode | `ngx_http_strata_phase.c` | Không có bundle; engine lỗi/panic (`STRATA_E_INTERNAL`); vượt `strata_cpu_budget` (`STRATA_E_BUDGET`); open cho qua, closed 503 kèm Event ID. Socket sự kiện đầy hoặc agent chết: request không đổi ở cả hai mode, chỉ đếm DROPPED |
| Event sink | `ngx_http_strata_events.c` | Socket `AF_UNIX`/`SOCK_DGRAM` mỗi worker, mở trong `init_process`, `sendto(MSG_DONTWAIT)`; lỗi bất kỳ (EAGAIN, ENOENT, ECONNREFUSED) → bộ đếm 9. Buffer 8 KB tĩnh mỗi worker. C chỉ copy byte từ `strata_tx_event` |
| File metrics STRMET1 | `ngx_http_strata_events.c` | Master tạo trong `init_module` (tạm → `ftruncate` → header → `rename` → `mmap MAP_SHARED`), worker ghi slot `ngx_worker` bằng atomic 64 bit relaxed. Bộ đếm 0..20 đúng chỉ số của `agent/internal/shmmetrics`. Directive mới `strata_metrics_file` (mặc định `/run/strata/metrics`, cạnh control file) |
| Force-shadow (Q2) | `ngx_http_strata_bundle.c` | Đọc offset 324/328/336 cùng lần đọc control file dưới seqlock; tên kiểm `[a-z0-9._-]`, sai thì bỏ qua cả khối và log một lần mỗi worker. Generation đổi mà tên bundle không đổi: chỉ cập nhật cờ, không reload |
| Một tx, một sự kiện, một lần đếm | `ngx_http_strata_phase.c` (pool cleanup) | Sự kiện và metrics ghi trong cleanup của request chính (chạy cả khi client hủy, HTTP/2 RST_STREAM), cờ `emitted`/`counted`; internal redirect giữ verdict đầu |
| Status trong sự kiện | header filter, trang chặn, cleanup | Status thật của response; request không tới header filter (RST, 503 fail closed) dùng status đã gửi hoặc của verdict |
| Response sau khi hết budget | `engine/ffi/src/ffi.rs` | Lỗi tìm được khi test: `with_tx` chặn **mọi** lệnh FFI sau khi hết budget, nên `strata_tx_response_headers` không ghi status và data guard không chạy qua FFI (test cũ của R-01 gọi thẳng `Tx`). Lệnh response giờ không qua cổng budget (`with_tx_response`); test `engine/ffi/tests/budget_response.rs` |
| Lab | `deploy/lab/` | NGINX ghi `/run/strata/metrics` trên volume chung với agent (`--metrics-file`); `smoke.sh` tra sự kiện của request bị chặn thật (bỏ `strata-emit`) và kiểm `strata_metrics_file_up == 1` cho cả hai agent |

Khác kế hoạch:
- `strata_event_sink_t` không làm thành struct con trỏ hàm: chỉ có một bản cài đặt, ba hàm `ngx_http_strata_events_init_process`, `ngx_http_strata_event_send`, `ngx_http_strata_events_exit_process` đóng vai init/send/close (tiết kiệm dòng C; phần C đang sát 2.500).
- Mục 6 (giữ request sống khi có task thread pool): module không đưa task nào vào thread pool, kiểm tra chạy đồng bộ trong worker; đọc body qua `ngx_http_read_client_request_body`, NGINX tự giữ request. Không có code mới.
- Test gộp trong `t/060-fail-mode-events.t` (harness riêng như `t/004-reload.t`, 2 worker) thay vì 060/061/062: sự kiện, metrics và control file cần đọc giữa các request.

## 2. Test

`t/060-fail-mode-events.t`, 17 subtest: layout file metrics; request sạch; chặn (Block ID `STR-`, status 403, action BLOCK, policy); shadow (Event ID, status upstream); panic open/closed; budget open/closed (bundle CRS, body ~1 MB, `strata_cpu_budget 1ms`); không bundle open/closed; redirect (một sự kiện, một lần đếm); không có socket (DROPPED = 2, request không đổi); force-shadow mọi policy, một policy, dữ liệu sai; không có log alert/crit/emerg. RST_STREAM: `t/002-body.t` TEST 16 (tx giải phóng đúng một lần), chạy dưới ASan cùng đường gửi sự kiện trong cleanup.

## 1. Đã làm

| Mục | Ở đâu | Ghi chú |
| --- | --- | --- |
| Toxic helper | `tests/e2e/network_faults_test.go` (`toxic`, `degrade`) | Thêm toxic `latency` (120ms, jitter 80ms) + `slicer` (cắt gói 128±64 byte, delay 5ms) lên proxy giữa agent và control plane, chồng lên các lần bật/tắt (cắt mạng) |
| Không mất sự kiện | `TestEventsSurviveNetworkFaults` | Agent nối qua toxiproxy; đẩy 100 sự kiện trong khi cắt/nối mạng 2 lần; worker nói với agent qua socket cục bộ nên luôn gửi được, agent spool và gửi lại khi nối lại; kiểm **cả 100** tới event store |
| Không bundle hỏng | `TestBundleRolloutSurvivesNetworkFaults` | Rollout bundle v1 qua link chậm + cắt 1 lần giữa lúc tải; `FetchBundle` resume; kiểm control file đặt version 1 và `bundlefmt.Verify` gói đã tải |

**Thiết kế**: dùng harness e2e sẵn có — `startFleet` (có event store) cho sự kiện,
`startPlatform` (Postgres + MinIO + Deployer + Rollouts) cho bundle; chèn
toxiproxy giữa agent và CP như `TestNetworkOutageHeals` (W07). "Mất gói" mô hình
bằng `slicer` + các lần cắt; cả hai test bỏ qua khi `-short`.

## 3. Tự review

1. "Xong khi" có lệnh + output: mục 2.
2. Đường lỗi: sự kiện spool + gửi lại (agent/internal/batch); bundle tải resumable + verify chữ ký trước khi activate.
3. Giới hạn: vòng chờ có deadline (120s sự kiện, 180s rollout); 100 sự kiện.
4. Bảo mật: mTLS qua proxy; không secret trong log.
5. Ngoài thư mục: chỉ `tests/e2e/` (test), báo cáo, AGENTS.md.
6. e2e chạy trên host với docker (postgres, minio, toxiproxy).

## 4. Việc còn mở

- `slicer` là xấp xỉ "mất gói" ở tầng ứng dụng; mất gói thật ở tầng mạng cần netem, ngoài phạm vi test tích hợp này.

# W17-G2-01: GeoIP aggregates

Source reviewed: `control-plane/ingest/geoviews.go` of `1cac91c`, `04b21f9`,
`d645ffc` (branch `w17-geoip-map-platform`). Rewritten: the source views gave
wrong numbers. PO decision 19/10: materialized views with `uniqCombined64`.

## Defects of the source

| Defect | Effect | Now |
| --- | --- | --- |
| Views counted `count()` of inserted rows; the events table (ReplacingMergeTree) keeps a resent event twice until it merges | Every batch resent after a write timeout (batcher, 5 s) or a crash between the ClickHouse write and the watermark commit counted twice, forever (aggregates never merge it away) | `uniqCombined64State(block_id)`: an event counts once; test resends a batch and reruns the backfill |
| Grid table `SummingMergeTree` with `lat`, `lon` as plain columns | SummingMergeTree **adds up** non-key numeric columns on merge: coordinates of a cell grow with its rows | No coordinates stored: the center of the geohash cell is computed at read time (checked against ClickHouse `geohashDecode`) |
| Attack type from `score_sqli`/`score_xss` | The engine scores layers (`protocol`, `managed`…), the fleet maps `layer_scores["sqli"]`, always 0: everything was "anomaly" | Classified from the matched rule IDs (`ingest.AttackTypeSQL`, ranges of strata-overview.md › Rule ID) |
| "Top attack type" as `any(attack_type)` | An arbitrary type, not the most frequent | `argMax` over per-type distinct counts |
| `lat != 0 AND lon != 0` on columns that are `Nullable(Float64)` on main | Wrong filter (0 is a valid coordinate, NULL is unknown) | `IS NOT NULL` |
| Unversioned (legacy, unverified) location used | Data that Get/Search withhold appeared on the map | Same rule as `sanitizeStoredGeoIP` |
| No backfill | Map empty for events stored before the upgrade | One backfill per day of events, marked done, safe to rerun |
| `ALTER ... TTL` style | — | TTL set only when it differs (an ALTER rewrites parts) |

## What

- `control-plane/ingest/geoagg.go`: tables `events_geo_minute_v1`
  (minute, policy, action, attack type, country, ASN, `any(as_org)`) and
  `events_geo_grid_v1` (5 minutes, geohash 4, policy, action, attack type,
  country, `any(city)`), views, retention (`-geo-aggregates-months`, default
  13), backfill, read functions `GeoByCountry`, `GeoByASN`, `GeoByCell`
  (the REST API is W18-G2-01).
- Not here: "site" (events carry no connector group yet), the weekly
  `.mmdb` download job (next PR), query load acceptance (W17-Q-01).

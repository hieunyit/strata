# W18-R-01: more CRS rules imported automatically

Source reviewed: the CRS changes of `517c5f1` (W17 branch): it raised the
importer's default to paranoia level 2 and committed the PL2 rules into
`rules/crs`, the default core pack, for every route. Not taken: PL2 is a
per-route choice in shadow first (W17-S-01), and a default pack with PL2
raises false positives everywhere. This change raises the rate of the
active paranoia level 1 rules instead.

## Result

| | Week 8 (`a37eeb2`, 13/10) | Now |
| --- | ---: | ---: |
| CRS 4.25.2 rules read | 392 | 392 |
| Imported | 148 | **150** |
| PL1 detection rules active in a default CRS | 159 (counted) | 153 |
| Rate | 93% | **98%** |

The denominator changes because six rules were counted as missing although
a default CRS never runs them: they need a crs-setup option REQUEST-901 does
not set (argument name/value length and count, file sizes: 920360–920410;
UTF-8 validation: 920250). They are now listed as "disabled by default"
with the option.

## Importer changes (`tools/strata-import-crs`)

- `REQUEST_BODY_LENGTH` → `request_body` with transformation `length`
  (alone in its condition): **920640** (body without Content-Type).
- A selector pattern that spells a finite set of names (literals,
  `\xHH`, `\`-escaped punctuation, `?`; at most 16 names) becomes exact keys,
  with a note in the import report (a name merely containing the pattern no
  longer matches): **921250** (`REQUEST_COOKIES:/\x22?\x24Version/` →
  `"$Version`, `$Version`).
- First link `&TX:x @eq 1` / `TX:x @eq 1` with `tx.x` unset by default →
  "disabled by default (crs-setup tx.x)", counted with the plumbing.
- Left out: 920190, 943110 (compare captured values at run time), 920250
  and 920360–920410 (off by default).

# W20-S-01: policy templates, `api` for APIs with an OpenAPI description

Plan, done when: the `api` template has tests.

PO decision (21/10): a template is a **starting point**, not live
inheritance. Its spec is copied into the policy's first version, with the
fields the request sets on top. The policy records the template's name and
version (`spec.template`) and is on its own afterwards. A later template
change never reaches a running policy without a new version, replay and
approval.

## Templates (`control-plane/policy/templates.go`)

| Template | Settings (all start in `shadow`) |
| --- | --- |
| `base` | the engine's defaults |
| `web` | `oversize: pass` (uploads); database error messages in responses reported |
| `api` | `oversize: block` (as `nginx-module.md` sets for the API template); at most 256 arguments inspected (more go by oversize); `fail_on_findings: block` (when enforced, a CPU budget that runs out on a request with findings fails closed); database errors and JSON Web Tokens in responses (tokens masked when enforced); credential fields (`password`, `token`, `access_token`, `refresh_token`, `api_key`, `client_secret`, `otp`, …) never in events |

Checking requests against the OpenAPI document itself (the positive model,
`unknownFields: block`) is W21's schema work. This template is what an API
route can enforce today.

## API and UI

- `GET /v1/policyTemplates`, with permission `policies:read`, lists the
  templates: name, version, description, spec.
- `POST /v1/policies?template=api` creates the policy from the template
  (permission `policies:write`). The body `policy.spec` overrides
  top-level fields, for example `mode`. An unknown template gives 400.
  The query parameter keeps the request body as before, so existing
  clients are unaffected.
- `PolicySpec.template` (field 15) carries the reference and is kept by
  later versions.
- The **Policies** page has a "New policy" button (operators and admins).
  The dialog takes an id, a name and a template (`api` by default) and
  shows the template's description. It creates the first version as a
  draft and opens the policy.

## Tests

- `control-plane/policy/template_test.go` checks that:
  - every template is valid and starts in shadow;
  - `api` has exactly its settings;
  - the request's fields win;
  - the policy gets a copy, so changing it never changes the template;
  - an unknown template or a bad reference is refused.
- `control-plane/admin/policy_template_test.go`: listing; creating from
  `api` and `web`; the reference survives a later edit; an unknown
  template is refused.
- `control-plane/admin/template_gateway_test.go`, through the REST
  gateway and RBAC: `GET /v1/policyTemplates` as a viewer;
  `POST /v1/policies?template=api` stores the merged spec; an unknown
  template gives 400; a viewer cannot create (403).
- `ui/src/__tests__/PolicyTemplates.test.tsx`: the dialog validates the
  id, shows the description, sends `template=api`, and reports a 409.

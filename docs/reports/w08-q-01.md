# Báo cáo W08-Q-01 · Conformance trong CI

Nhiệm vụ: W08-Q-01
Nhánh: `W08-Q-01-conformance-ci`
Công cụ: Claude Code

## 1. Đã làm

| Mục | Ở đâu | Ghi chú |
| --- | --- | --- |
| Corpus conformance v1 | `conformance/corpus/v1.jsonl` | 10 request kèm quyết định mong đợi (`allow`/`block`): sạch, stub `STRATA-TEST-BLOCK` (query + body), SQLi trên args (và biến thể sạch không khớp), virtual patch `block_alone`, null byte, encoded dot-segment, path sạch có dấu chấm |
| Runner qua engine | `engine/compiler/tests/conformance.rs` | Nạp corpus, biên dịch một bundle thật (rule `score`/`block_alone` tiêu biểu), chạy từng request qua `Tx` và so khớp `action`. Ghim hành vi chung engine + connector: lớp protocol built-in, stub rule, scoring |
| make target | `Makefile` (`test-conformance`) | Chạy conformance qua engine + differential (go-net-http/spring, W08-R-01) |
| CI | `.github/workflows/ci.yml` (job `conformance`) | `dorny/paths-filter` chỉ chạy khi PR chạm `engine/**`, `connectors/**` hoặc `conformance/**`; dựng image dev rồi `make test-conformance` |
| Tài liệu | `conformance/README.md` | Mô tả corpus v1 + cách chạy + cổng CI |

**Quyết định kỹ thuật**: runner đặt ở crate `strata-compiler` (không phải
`libstrata`) để tránh vòng phụ thuộc — compiler phụ thuộc engine, nên test ở đây
vừa biên dịch bundle vừa chạy engine. Corpus chọn các hành vi **ổn định** (lớp
protocol built-in, stub, một rx/một block_alone nội bộ) nên không vỡ khi nội dung
gói rule tiến hóa; vẫn phủ đúng đường quyết định mà engine và connector dùng chung.

## 2. Xong khi → kết quả đo

| Điều kiện | Lệnh | Kết quả |
| --- | --- | --- |
| Corpus conformance v1 chạy | `cargo test -p strata-compiler --test conformance` | `test result: ok. 1 passed` — 10/10 case khớp quyết định mong đợi |
| Chạy mỗi PR của engine/ và connectors/ | job `conformance` trong `ci.yml` | `dorny/paths-filter` relevant = `engine/**`, `connectors/**`, `conformance/**`; chạy `make test-conformance` khi khớp |
| Target gộp | `deploy/dev/run.sh make test-conformance` | PASS: conformance engine (1) + differential (`conformance/differential` go test) |

## 3. Tự review

1. "Xong khi" có lệnh + output: mục 2.
2. Đường lỗi: runner `panic!` kèm tên case + action/score/rules khi lệch, dễ chẩn đoán; corpus bỏ dòng trống.
3. Giới hạn: khẳng định `checked >= 10` để corpus không bị rỗng âm thầm.
4. Bảo mật: không secret; chỉ dữ liệu request tổng hợp (`api.example.test`).
5. Ngoài thư mục: `conformance/`, `engine/compiler/tests/`, `Makefile`, `.github/workflows/ci.yml`, báo cáo, AGENTS.md.
6. Chạy xanh cả rust test lẫn go differential.

## 4. Việc còn mở

- Corpus v1 ghim quyết định engine; khi có 5 connector, mở rộng để chạy cùng corpus qua từng connector và so khớp (mục tiêu gốc của `conformance/`).

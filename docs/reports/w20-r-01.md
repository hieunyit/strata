# W20-R-01: semantic detector false positives, measured

Plan, done when: the semantic detectors' FP on the replay corpus goes down,
per S's report.

User decision (20/10): build a measurement tool, run it on the replay
samples of staging (read only, no deploy), and tune a detector only on a
real false positive, checking each change against recall.

**Result: no false positive to tune.** Nothing in the corpora, in the
look-alike values, in synthetic uploads or in six days of staging pilot
traffic matched a semantic rule on a benign request. No detector was
changed. The tool and a regression gate are the deliverable; the plan's
condition (FP goes down) has nothing to act on until a real false
positive shows up.

## The source branch's change was not taken

Commit 65d0ce2 (W20-R-01 on the source branch) made `detect_sqli` skip
fingerprint `1&1` whenever the input has `&&` and no quote or comment.
That is a blanket exemption: `1 && 1=1`-style boolean probes have the same
shape. It was also written against a false positive the rule never
raises. 942100 checks the detector's match with a CRS regex (keywords,
quotes, `=`), and `5 < 10 && 10 > 2` fails it. The look-alike value lists
of that commit are kept as `corpus/fp/semantic/`.

## The tool: `strata-replay semantic`

```text
strata-replay semantic --bundle b.sbn --pubkey k.pub [--policy name] [--threads N]
    [--corpus <repo>/corpus] [--values label=file,...] [--uploads N]
    [--md report.md] [--title T] [samples.parquet...]
```

- Finds the bundle's rules with a semantic operator (`detect_sqli`,
  `detect_xss`, `detect_cmdi`, `detect_ssti` in any condition).
- Runs every request through the engine as the connector does, and counts
  per detector and label: requests matched, report-only (paranoia level in
  shadow), alone (no other rule matched), per rule, per field, and per
  SQLi fingerprint (libinjection token types of the value the rule matched).
- Labels: `benign` (corpus pilot + synthetic), `benign-…` value lists (FP),
  `benign-upload` (`--uploads N`: multipart uploads of 2–32 KiB of random
  bytes, like the staging pilot's), the attack types of the corpus
  (detection rate), and `replay` (traffic samples, unlabelled: candidates).
- Keeps at most 20 example values per detector, from benign and replay
  labels only. Samples are anonymized before they are stored, and the
  corpora hold no personal data.

The values come from a new opt-in, `Tx::keep_match_values()` (libstrata):
the transformed value of each match, unmasked. It is off by default, so the
connector's path is unchanged, and only offline tools turn it on.

Regression gate: `engine/replay/tests/semantic.rs` (part of
`cargo test --workspace`). On the CRS pack (PL1 enforced, PL2 shadow), the
semantic rules match none of the 3,000 benign corpus requests, none of the
look-alike values and none of 300 binary uploads. Detection on the attack
corpus stays at least at today's (SQLi ≥ 43%, XSS ≥ 58%), so a tuning that
loses recall fails.

## Measurements (20/10, origin/main bf0ba5c + this change)

Bundle: every IR rule file of `rules/crs`, `gaps`, `virtual-patches`,
`sigma`, `et-open`, `bots` (9,078 rules); policy `example-api` enforce,
`crs_paranoia: 1`, `crs_paranoia_shadow: 2`. 10,363 requests in 41 s on
5 threads (CPUs 6–10).

| Label | Requests | SQLi rules (942100, 942101) | XSS rules (941100, 941101) |
| --- | ---: | ---: | ---: |
| benign (corpus) | 3,000 | 0 | 0 |
| benign-sqli-edge (`sqli-benign.txt`) | 50 | 0 | 0 |
| benign-xss-edge (`xss-benign.txt`) | 32 | 0 | 0 |
| benign-upload (random bytes) | 5,000 | 0 | 0 |
| sql-injection | 807 | 357 (44.2%) | 0 |
| xss | 529 | 25 (4.7%) | 314 (59.4%) |
| command-injection | 479 | 42 (8.8%) | 0 |
| path-traversal | 466 | 0 | 0 |

In every attack row the semantic rules never matched alone: another CRS
rule matched the same request too. Most common SQLi fingerprints on the
attack corpus: `&1of(` 59, `UEv,f` 57, `s&sos` 44, `UE1c` 30, `s&1c` 27.

## Staging (read only)

- **No replay samples exist.** On staging, prod-sim and the lab, the object
  stores hold bundles only. Sampling needs `-replay-sampling-approved` on
  the control plane (a privacy approval), and no environment runs with it.
  I did not turn it on.
- **Event store** (`strata-staging-clickhouse-1`, 13/10–20/10, 225,424
  events). The benign pilot client (`172.18.0.18`, alternating
  `/v1/verify` and `/v1/upload`) has **0** semantic matches. The pilot
  attacker (`172.18.0.19`) has 2,445. The host (`172.18.0.1`) has 4, all
  test attacks sent by hand (`1'OR'1'='1`, `<script>alert(…)`). These are
  the "942100: 4 events / 3 clients" and "941100: 1" rows of the 13/10 FP
  table, already explained in `w10-s-01.md`: not false positives.
- **Uploads were not inspected on staging.** 220,399 of the benign
  `/v1/upload` requests are `action=error` with no rules: staging runs
  `v0.10.0-rc.4`, from before the large-body fixes (#28: #85, #87, #93,
  #99), and fails open on them. So staging says nothing about uploads. The
  `--uploads` run above covers that gap on the current engine: 0 of 5,000.
  About 260,000 verify requests were inspected (no event = allowed).
- Prod-sim has only test traffic from the host (GoTestWAF and others), no
  benign stream, so it was not used.

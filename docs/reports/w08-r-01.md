# Báo cáo W08-R-01 · Fuzz và differential

Nhiệm vụ: W08-R-01
Nhánh: `W08-R-01-fuzz-differential`
Công cụ: Claude Code

## 1. Đã làm

| Mục | Ở đâu | Ghi chú |
| --- | --- | --- |
| Fuzz target cho lớp FFI | `engine/fuzz/fuzz_targets/ffi.rs` (+ `Cargo.toml`, `run.sh`) | Lái trọn vòng đời transaction qua C ABI `libstrata-ffi`: `strata_tx_new` (có/không `strata_conn_t`, cờ force-shadow), `request_line`, `request_headers`, nhiều `request_body_chunk`, đường response (`response_headers`/`body_chunk`/`buf_free`), `verdict`, `event` vào buffer cố định, `free`. Mục tiêu: biên unsafe — mọi cặp con trỏ/độ dài connector truyền vào không gây lỗi bộ nhớ |
| Nhánh ASan | `engine/fuzz/run.sh` (`STRATA_FUZZ_ASAN=1`), `deploy/dev/Dockerfile` (nightly + rust-src) | Build nightly `-Zsanitizer=address -Zbuild-std` để bắt lỗi bộ nhớ thật, không chỉ crash tình cờ |
| Harness differential | `conformance/differential/` (Go) | Hai profile: `go-net-http` (parser thật `http.ReadRequest`) và `spring` (mô hình framing nghiêm ngặt RFC 7230 của Servlet container Tomcat/Coyote). So **framing** (method, target, cách quyết định độ dài body qua Content-Length vs Transfer-Encoding) — nơi sinh request smuggling. Gắn cờ phân kỳ, có corpus + test |
| Tài liệu | `conformance/README.md`, `engine/fuzz/README.md` | |

**Quyết định kỹ thuật**: differential dùng parser Go thật cho `go-net-http`; `spring`
là mô hình framing (Tomcat/Coyote), ghi rõ trong code/README. Trọng tâm là framing
body (CL/TE) vì đó là vector smuggling; mỗi ca phân kỳ là ứng viên corpus
conformance (W08-Q-01) và khớp rule protocol mơ hồ của Strata
(100126/100128/100139, `block_alone`).

## 3. Lệnh khởi động fuzz 72 giờ và cách theo dõi

```bash
docker run -d --name strata-fuzz-72h \
  -v "$PWD:/src" -w /src \
  -e GOMODCACHE=/src/build/go/mod -e GOCACHE=/src/build/go/cache \
  strata-dev:latest \
  bash -c 'rustup toolchain install nightly --profile minimal --component rust-src \
           >/src/build/fuzz/nightly-install.log 2>&1; \
           exec env STRATA_FUZZ_ASAN=1 engine/fuzz/run.sh 259200 ffi'

docker logs -f strata-fuzz-72h          # tiến độ
ls build/fuzz/ffi/artifacts/            # crash (nếu có)
```

Trạng thái lúc viết báo cáo: container `Up`, đang cài nightly/ build target ASan,
sau đó fuzz liên tục. Không ngồi chờ theo yêu cầu nhiệm vụ.

## 4. Tự review

1. "Xong khi" có lệnh + output: mục 2.
2. Đường lỗi: FFI target chỉ gọi API C ABI (đã bọc `catch_unwind` ở libstrata-ffi); cursor đọc input có chặn trên; differential profile `spring` từ chối (không panic) các ca xấu.
3. Giới hạn: cursor `take` kẹp theo bytes còn lại; header tối đa 16, response header tối đa 8.
4. Bảo mật: không log bí mật; fuzz corpus/artifact dưới `build/` (gitignore).
5. Ngoài thư mục: `engine/fuzz/`, `conformance/`, `deploy/dev/Dockerfile` (nightly cho ASan fuzz), báo cáo, AGENTS.md.
6. `go vet` sạch; fuzz crate không nằm trong `clippy --workspace` (build riêng bằng run.sh, như trước).

## 5. Việc còn mở

- Bản 72 giờ chạy target `ffi` (deliverable của R-01); các target khác chạy bằng `run.sh 259200` (mọi target song song) trên máy fuzz chuyên dụng — nặng RAM nên không bật tất cả cùng lúc ở máy dev này.
- `spring` là mô hình framing, không phải Tomcat thật; đủ để sinh ca smuggling. Nếu cần đối chiếu Tomcat thật, thêm profile chạy container Tomcat sau.
- Crash (nếu 72 giờ sinh ra) → `gh issue create` theo mục 2.

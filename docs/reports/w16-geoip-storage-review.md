# W16 GeoIP persistence and migration review

This continues the W15–W16 source selection on main after #241–#243. The initial focused real-ClickHouse regressions failed: GeoIP columns were missing, the old branch's Float32 coordinates were not upgraded, and SearchEvents returned a partial page as success after a simulated driver stream failure. Raw failing output is retained.

Schema initialization and EnsureColumns now add country, region, city, nullable Float64 latitude/longitude, nullable UInt16 accuracy, ASN/organization and the database pair fingerprint. Supported legacy numeric coordinate columns upgrade to nullable Float64. Unsupported types fail explicitly without modifying their raw values. Existing rows are retained. Get/Search clear all unversioned location/ASN metadata, because the old branch could retain producer-supplied fields and zero defaults do not prove a known location. INTERNAL is retained only when the stored claimed client address parses as internal; that does not independently attest the IP origin. Raw legacy values are not erased. A versioned genuine (0,0) remains a valid coordinate pair.

Native batch append, point lookup and paginated search include the metadata. Existing masked context, inspection flags, sampled rule costs and FINAL/latest-row semantics remain intact. Search now checks rows.Err and fails the complete result when the driver stream fails, rather than returning incomplete data with a successful total. The deterministic fault test wraps a real ClickHouse query and injects an error after its first row; it is not described as a live network outage.

## Acceptance

Owned ClickHouse 25.8.33.6 in the existing private PostgreSQL lab network, with a fresh random credential and a unique database per test. The separate 20-million-event fixture was not used. Tests exercise both missing columns and old Float32 schemas, idempotent migration, old-row retention/raw values, actual MMDB City/ASN ingestion, discarded forged/missing metadata, private IPs, nullable coordinates, real zero coordinates, duplicate ACKs, unmerged retry rows, preserved event context/costs and newest-row search. A negative schema test preserves a nonnumeric raw value while refusing an unsupported coordinate type.

After the initial focused failures, full ingest race tests passed in 14.983s and lint 0 issues. The first concurrent full-CP run found a newly written fixture error: its supposed newer row used test-start+1s, which could be older than the actual initial ReceivedAt. The fixture now uses stored ReceivedAt+1s and retains the strict latest-row assertion. Final full control-plane `go test -race -count=1 -timeout 10m ./...` passed against real PostgreSQL and ClickHouse: API 14.668s, Fleet 39.394s, ingest 15.281s, local auth 28.675s, store 20.414s; full lint 0 issues. Both that initial failure and final output are retained.

Before merge, a regression against the initial storage candidate 772d75d showed that unversioned country/city/ASN still leaked through while coordinates were withheld. The read guard now clears all of those fields and shares the canonical bounded IP parser/private classification with the resolver. The regression fails on that previous candidate; the complete current CP race suite passes against both real databases (ingest 15.593s, API 14.123s, Fleet 39.596s, store 21.341s), lint 0. A further focused test rejects public/malformed addresses falsely labeled INTERNAL, and accepts valid private/mapped-port forms while clearing fake city/ASN/coordinates (1.095s, lint 0). Evidence is retained.

This completes the selected DB migration/persistence path, not runtime startup activation. The next change wires operator-provided City/ASN files into server startup; no automatic weekly download/object-store job, map or operational Gate is claimed. Tests use synthetic MMDB data and small isolated tables, not a full commercial database or large-table migration benchmark.

Self-review: no runtime dependency/proto/rule/ABI changes; all SQL inputs remain parameterized apart from existing trusted table/constant column names; missing coordinates stay nullable; lookup failures do not discard security events; errors propagate without partial-success results; idempotency and raw historical values are preserved. Private fixture credentials are kept outside the repository and excluded from evidence.
